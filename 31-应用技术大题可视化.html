①数据流图（目标 10 分）：先读说明再读图；口诀——父图有子图、出入要平衡、加工不黑洞不奇迹。模板详见《04-应用技术答题模板》。

⚖️ 三大规则 + 黑洞/奇迹图解

规则1 父子图平衡（10号题62 同源）子图的输入/输出数据流必须与父图对应加工的完全一致（数量与方向），既不能多也不能少
规则2 加工要闭环每个加工既有输入又有输出；只有进没有出=黑洞，只有出没有进=奇迹
规则3 命名规范数据流必须命名（不能同名异物）；外部实体/数据存储不能直连——外部→外部、存储→存储都要经过加工
答题三步① 对照说明逐条找"提到的流图上有没有" ② 数每个加工的出入流 ③ 检查父图↔子图边界

📖 完整范例：医院预约挂号 0 层图（16号①-3 同源）

【题目描述】某医院预约挂号系统流程如下：患者提交预约申请；系统根据排班信息判断号源，有号则生成预约单并扣减号源，无号则返回满员告知——两种结果都要通知患者；患者就诊当天凭预约单在取号处理取得取号凭证，取号信息写入挂号记录；系统每晚从挂号记录汇总当日挂号数据，交清单生成加工产出就诊清单给医生。→ 先盖住下图，自己拿笔照描述画一遍 0 层图，再对照。
读图口诀黄矩形=外部实体（系统外的人/组织）；蓝框=加工（必有编号）；绿框=数据存储（左侧双竖线）；每条箭头都有名字
检查口（找错就这三条）存储↔存储不直连、外部实体↔外部实体不直连、每个加工有进且有出（黑洞/奇迹）
补流技巧说明里每个动词短语（提交/生成/通知/汇总）对应一条流；名字用说明原词，方向看"谁给谁"

🔀 联系类型判定器 + 随机出题

📋 E-R → 关系模式三规则（题23、24 同源）

联系类型转换方法记忆
1:1并入任一端（加对方主键作外键）随便并
1:n并入 n 端（n 端加 1 端主键作外键）并入多的一方
m:n独立成表：两端主键 + 联系自身属性，主键=两端主键组合多对多必须独立
主键/外键填空主键：能唯一标识且非空；外键：参照另一表主键 FOREIGN KEY ... REFERENCES（12号题27）
弱实体没有自己的主键、依赖宿主实体存在（如"家属"依赖"职工"）：主键=宿主主键+自己的区分属性
SQL 模板建表 CREATE TABLE、约束 PRIMARY KEY / FOREIGN KEY / CHECK；查询 GROUP BY + HAVING（27 号页签有全套）
踩坑m:n 联系的属性（如"成绩"）放在联系表里，不放任何一端实体表

📖 完整范例：宿舍管理 E-R 图（16号②-3 同源）

【题目描述】某宿舍管理系统：每栋楼栋拥有多间宿舍，每间宿舍只属于一栋楼；每间宿舍入住多名学生，每名学生只入住一间宿舍（入住需登记入住日期与床位号）；每名宿管员负责管理多栋楼栋，每栋楼由一名宿管员负责。→ 先自己画：圈出实体 → 两两读句子定联系和类型 → 标主键，再对照下图。
读图口诀黄矩形=实体（主键下划线）；紫菱形=联系；联系两端的 1/n 就是转换依据
转关系模式1:n 并入 n 端（本例全部 1:n）：楼栋表加宿管员工号、宿舍表加楼栋号、学生表加宿舍号——都是"1 端主键当外键"
联系属性挂哪只属于"关系"的属性挂菱形（入住日期/床位号），转模式时跟着进 n 端表，不放实体表

🧩 五类高频算法套路卡

链表类遍历 p = p->next；尾判 p != NULL；插入先接后断 s->next = p->next; p->next = s
二分类循环 lo <= hi；右半 lo = mid+1；左半 hi = mid−1；mid = (lo+hi)/2
排序类双指针分区、temp 交换三行；内层边界 j<n−1−i（冒泡每趟少一个）
字符串类结尾判 s[i] != '\0' 或 i<len；累加器初值 = 0；乘积器初值 = 1
递归类先写出口（if n<=1 return …），再写自调用 f(n−1)+…；DP 用数组打表
矩阵/数组类下标 0 起 vs 1 起看题目；对角/边界元素单独处理

📜 六大设计原则（10号题42、49-53 同源）

开闭原则对扩展开放、对修改关闭——所有模式的共同目标
单一职责一个类只负责一件事
里氏替换子类必须能替换父类（is-a）
依赖倒置依赖抽象接口，不依赖具体实现
接口隔离多个专用接口 > 一个胖接口
迪米特法则只与直接朋友通信，减少耦合

候选键：属性闭包三步（题12、35 同款）

R(A,B,C)，F={A→B, B→C}：①只出现在箭头左边的属性先进候选（A）②从 A 出发闭包：A→B→C，得 {A,B,C} 全覆盖 ③A 就是候选键。口诀：只出左边的入候选，闭包盖全属性即成立。
💼 ACID 对号：原子性=全做或全不做、一致性=状态合法、隔离性=并发互不干扰、持续性=提交永久生效（题13）。并发四问题：丢失修改、脏读、不可重复读、幻读——时间线逐个看下面的表。

并发四问题：画时间线就懂（题13-15 + 幻读，高频）

问题30 秒时间线特征一句话
丢失修改T1 读 x=100，T2 读 x=100；T1 写回 110，T2 写回 105 → 110 被 T2 覆盖丢失两个写互相覆盖
脏读T1 改 x=105（未提交），T2 读走 105；T1 回滚 → T2 手里的 105 从未存在过读到了未提交的数据
不可重复读T1 读 x=100；T2 改成 105 并提交；T1 再读变 105 → 同一事务两次读值不同两次读之间被别人 UPDATE
幻读T1 统计"成绩>90"得 5 行；T2 INSERT 一行 95 分并提交；T1 再统计得 6 行两次读之间被别人 INSERT/DELETE，行数变了
易混分界：同一行的值变了=不可重复读；多出/少了行=幻读。口诀：改丢=丢失修改、读脏=脏读、读变=不可重复读、行变=幻读。

S/X 锁兼容矩阵（题16）

已持有 ↓ / 申请 →S（共享锁·读）X（排他锁·写）
S✔ 兼容 可多读✘ 冲突
X✘ 冲突✘ 冲突
记忆：S 与 S 相容（大家都能读），X 谁都不容。两阶段锁协议 2PL（先加锁阶段后解锁阶段）→ 保证可串行化，但不预防死锁（题17）。

三级封锁协议 → 各防什么（高频）

级别规则防住
1 级修改前加 X 锁、事务结束才放（读不加锁）丢失修改
2 级1 级 + 读前加 S 锁、读完即可放丢失修改 + 脏读
3 级1 级 + 读前加 S 锁、事务结束才放丢失修改 + 脏读 + 不可重复读
记法：X 锁一律到事务结束；S 锁越晚放防得越多——读完就放=2 级，撑到事务结束=3 级。

活锁 vs 死锁（题43 扩展）

活锁死锁
现象某事务永远轮不上锁（总被别人抢先，单个饿死）两个以上事务互相等待对方的锁，全体卡死
应对先来先服务排队预防：一次封锁法 / 顺序封锁法（题43）；诊断：等待图（事务=点、等待=边，出现回路=死锁）、超时法

🧯 UNDO/REDO 判定与检查点四事务图（高频考图，点击 T1-T4）

判定只问一条：日志里有没有 <T, commit> 记录（不是看数据落没落盘——数据页上没有"属于谁"的标记，只有日志能判）。没 commit → UNDO 撤销（反向写旧值，保原子性）；有 commit → REDO 重做（正向写新值，保持久性）。敢全量重做靠幂等：同一个值写几遍结果不变，分不清落没落盘就照日志全来。
点击 T1-T4 任意事务：它处于什么状态、恢复时怎么处理、为什么

三类故障 × 恢复手段（题32 同源考点）

故障丢什么恢复手段
事务故障（死锁被杀/违反约束）什么都没丢只对该事务 UNDO，不影响别人（"病得轻"）
系统故障（断电/宕机）内存全丢，磁盘完好扫日志：未提交的 UNDO + 已提交未落盘的 REDO（"两个都要"）
介质故障（磁盘坏）数据本身没了重装后备副本 + 日志 REDO，不 UNDO（"数据没了"靠备份重做已提交的）
易错点：①判定看 commit 日志，不看数据落没落盘（也看不了）；②UNDO 反向写旧值、REDO 正向写新值，方向和值别配错对；③WAL=先写日志、后写数据（日志是恢复唯一依据，必须先落盘）；④恢复顺序先 UNDO 后 REDO。

恢复与新技术速查（题26/32/33/42）

原子性靠什么（题32）日志 + UNDO 回滚（故障时反向撤销未完成事务）
UNDO vs REDO 判定只看日志里有没有 commit：没有 → UNDO（反向写旧值·保原子性·当没发生过）；有 → REDO（正向写新值·保持久性·必须算数）
三类故障事务故障（只伤本事务）/ 系统故障（断电，内存丢磁盘在）/ 介质故障（磁盘坏，靠备份副本）
检查点 Checkpoint（题33）定期把日志/数据落盘——故障恢复时检查点之前的不用重做，缩小扫描范围
2PC 两阶段提交（题26）协调者先问全体"能提交吗"再下令提交——保证分布式事务原子性
数据仓库四特征（题42）面向主题、集成、相对稳定、反映历史变化（面向分析 OLAP，非 OLTP）
📝 SQL 题一半是"背句式"：分组过滤必 HAVING、模糊匹配 LIKE %/_、授权 GRANT、改数据 UPDATE、删数据留表 DELETE、删表才 DROP。

分布式 + 多表连接速记（题26、28）

2PC 两阶段提交：第一阶段协调者问所有参与者"能否提交"，全部同意后第二阶段才正式提交——保证分布式事务的原子性（题26）。
分布式透明性三级（题48，高频）：分片透明（不用知道数据怎么分片，级别最高）> 位置透明（不用知道数据在哪个场地）> 局部数据模型透明（不用知道局部用什么 DBMS）——对用户越"省心"，透明级别越高。
外连接（题28）：学生 10 行（2 人无选课）LEFT JOIN 选课 8 行 → 结果 10 行（没选课的学生也保留，选课列填 NULL）。内连接才是 8 行。

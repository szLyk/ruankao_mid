🪜 两个对称过程：发送方自上而下逐层加头（封装），接收方自下而上逐层去头（拆封装），中间结点只拆到自己那一层。注意：只有 2~7 层加头；链路层是唯一带"帧尾"的层；物理层不封装。

发送方：自上而下逐层加头（以浏览器访问网页 80 端口为例）

色块口径与"数据封装"动画一致：TCP头 IP头 帧头 帧尾FCS 应用数据

中间结点与接收方：只拆到自己那一层

交换机（第2层）：收帧 → 验 FCS → 摘帧头看 MAC → 查 MAC 表选端口 → 换一个新帧头再发。第 3 层以上的内容它从头到尾没看过
路由器（第3层）：再往上一层，看目的 IP 查路由表定下一跳，TTL 减 1，然后整帧重建——源/目的 MAC 全换成新链路上的地址——再发往下一跳
接收主机：自下而上剥头——FCS 错 → 丢帧；MAC 不是自己 → 丢；IP 是自己 → 摘 IP 头；最后按目的端口 80 把数据交给监听该端口的进程
全程规律：帧头每过一台路由器换一次；IP 头和里面的 TCP 段、应用数据一路不变（除 TTL 减 1）——IP 端到端不变，MAC 每跳都变

三个必背结论

① 头与尾只有 2~7 层加头，物理层无封装；链路层是唯一带"尾"（FCS 校验）的层
② 对等层通信每层加的头只由对端同一层拆：TCP头→传输层、IP头→网络层、帧头→本跳链路层
③ PDU 名称链（必背）报文 → 段 → 包 → 帧 → 比特（自上而下）；TCP/IP 实际把 5~7 层合并进应用层，考试按 OSI 七层口径答
🔗 一句话：物理层只有一串 0101，成帧就是把它切成一个个有格式的包；MAC 地址就是帧头里"送给谁 / 谁发的"那个本地门牌。

以太网帧结构（点击色块看说明）

帧长：64 ~ 1518 字节（不含前导码）——最小帧长 64B 是 CSMA/CD 的要求：帧太短，冲突信号还没传回来你就发完了，检测不到冲突。

网卡怎么"收一个帧"（成帧的逆过程）

1. 从网线上收比特流，认出前导码 → 知道一帧开始了
2. 收满一帧，用 FCS 重算 CRC → 不一致 = 传输出错，整帧丢弃
3. 目标 MAC 是自己 / 广播 / 组播才收下；别人的帧直接丢（抓包工具 = 开混杂模式全收）
4. 看类型字段：0800 → 交给 IP 层；0806 → 交给 ARP 处理
5. 层层上交——就是"数据封装"标签页动画的反向播放
🎯 一句话主线：发送方自上而下加头、接收方自下而上剥头；交换机只看 MAC，路由器只看 IP。必背结论：IP 地址端到端不变（NAT 除外），MAC 地址每过一个路由器换一套。

对等层：同层之间"隔空对话"

两台机器的同一层在逻辑上直接对话：你的 TCP 和服务器的 TCP 讨论序号与确认，你的 IP 层和服务器的 IP 层讨论地址——教科书图上那排虚线就是"对等协议"。
但物理上，数据必须下到最底层走介质、到对面再一层层爬上来。每一层的头部，只由对方的同一层来拆：TCP 头给传输层拆，IP 头给网络层拆，帧头给链路层拆。

三个必背结论

① 地址的变与不变IP 地址端到端不变（NAT 除外）；MAC 地址每过一个路由器换一套
② 设备看什么交换机看 MAC（转发帧）；路由器看 IP（转发包，重封帧）
③ 加头与剥头发送方自上而下加头；接收方自下而上剥头；各层头部由对端同层解析

概念速通：IP · 掩码 · 网络地址 · 广播地址是什么关系（小区类比）

192.168.20.96 ~ 192.168.20.111 这 16 个连号地址 = 一个子网（小区） ┌─ 96 ─── 网络地址 = 小区的「名字」（门牌全0，代表整个小区，不能给设备） │ 97 ~ 110 ── 14 个住户：真正能分配给设备的地址 └─ 111 ─── 广播地址 = 小区的「大喇叭」（门牌全1，喊一嗓子全小区收到）
东西本质说明数量
IP 地址设备的「小区名+门牌」，两截信息写在一起单独看不出分界在哪每小区 14 个可用（/28）
子网掩码不是地址——只声明「左边是小区名、右边是门牌」的尺子每台设备配置里 IP 和掩码必须成对出现同网段全网统一
网络地址门牌清零（主机位全0）= 小区名路由表写「去往这个网段」用它每小区 1 个（第一个）
广播地址门牌拉满（主机位全1）= 大喇叭ARP 喊话发给它每小区 1 个（最后一个）
判断同小区：两台设备掩码相同的前提下，各自套公式算出的网络地址一样 → 同网段可直接互通；不一样 → 必须走路由器。掩码不同，同一个 IP 算出的小区就不同——这就是下面的「换掩码换小区」。

易错点沉淀：4 个最容易绕晕的地方

① 为什么用 256 不用 255？8 个 1 = 255 是最大编号；一个字节有 256 个地址（0~255）。块长是「个数」→ 256−掩码值。类比 Java：数组最大下标 255，length 是 256。用 255−240=15 会漏数块起点自己（数数看：240~255 正好 16 个）
② −2 只用在「求可用主机数」主机位全 0 = 网络地址（路牌）、全 1 = 广播地址（喇叭），都不能给设备。求网络地址 / 广播地址 / 块长时不减——减了答案就没了。最小 /30：4−2=2 台，路由器互联专用
③ 网络位的内容是 IP 自己的位掩码的 1 只是「指位置」的筛子：1 的位置放行 IP 的位，0 的位置归零。96 = 0110|0000，前 4 位 0110 = 块号 6（96÷16=6）。网络位可以是 0（第 0 号小区就是 0000），不是「被 1 占着」
④ /N 记法与 9 个合法掩码值/N = 前 N 位全 1、后面全 0。掩码每段只可能是 0/128/192/224/240/248/252/254/255 这 9 个值——出现 200/160/100 → 非法干扰项，直接排除。A/B/C 类默认掩码 /8 /16 /24 是出厂规定，借几位是设计者选的

重叠与冲突：父子嵌套合法，同级重叠非法

100 在每层尺子下的小区（套娃结构）： /24 0~255 ⊃ /25 0~127 ⊃ /26 64~127 ⊃ /27 96~127 ⊃ /28 96~111 ⊃ /29 96~103 ⊃ /30 100~103 细块永远整体落在粗块内部 —— 部分在整体里 = 层级关系，不算冲突
✔ 合法：路由表重叠 → 最长前缀匹配（考点）多条路由都罩得住时，选前缀最长（最具体）的那条：去 101 的包，/30 比 /29 细，走 /30 那条
✘ 非法：同级兄弟块重叠同一个父块切出的兄弟块必须互不重叠、正好拼满；同一层级一片地址只能有一个主人。设备 A 配 /29、B 配 /30 抢同一片本地网段 = 配置错误，掩码不同救不了场
分配规则：①按块边界切干净，一块一个主人（没有"冲突后二选一"，只有"各归各块"）；②新需求从没分出去的块里拿；③单位是块不是散 IP（连网络/广播地址一起归块）；④分出去的块内部还能按需再切（VLSM 可变长子网掩码）——对上身份不变，对内自设小区
🤝 考点：三次握手=确认双方收发能力+防止失效旧 SYN 建空连接；四次挥手=半关闭（收到 FIN 的一方可能还要发数据）；TIME_WAIT 等 2MSL。序号规律：ack = 对方 seq + 1。
